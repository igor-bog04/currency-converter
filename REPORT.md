## 1. Источник данных и почему

Выбран **официальный XML Национального банка Молдовы (BNM)**:
`https://www.bnm.md/en/official_exchange_rates?get_xml=1&date=DD.MM.YYYY`.

Причины:
- официальный источник, бесплатный, без регистрации и API-ключа — нечему протухнуть или упереться в лимит;
- курсы даны относительно MDL, поэтому кросс-курс любой пары считается через MDL одной формулой: `курс = Value / Nominal`;
- у источника есть особенности (даты без публикации, ошибка 404), на которых можно честно проверить обязательное поведение из задания: откат по датам, офлайн-режим, кэш.

Минус — только XML, без JSON; разбор через `xml.etree.ElementTree`.

## 4. Где агент ошибся и что исправлялось вручную

### 4.1. Слабые тесты (Claude Sonnet 4.6, этап tests)

23 из 93 тестов **проходили без единой строки реализации**. Причина — проверки вида:

```python
with pytest.raises((ValueError, TypeError, Exception)):
```

`Exception` ловит любую ошибку, включая `NotImplementedError` из заготовок, поэтому тест «ноль не принимается» проходил, хотя проверки нуля ещё не было. Названия вроде `test_connection_error_raises_or_returns_none` показывали, что агент не определился с поведением.

**Исправление:** агенту (Gemini) поставлена задача ввести конкретные исключения `SourceUnavailableError`, `NoRatesForDateError`, `AmountValidationError` и проверять именно их. Итог: 0 passed, 78 failed, 16 errors — все падения по правильной причине (`NotImplementedError` / `ImportError`).

Частично это **пробел спецификации**: `contracts/bnm-data-contract.md` описывал поведение словами («404 — нет курсов на дату», «таймаут — источник недоступен»), но не задавал типы ошибок. Вывод: контракт ошибок нужно фиксировать в спецификации явно.

### 4.2. Подгонка кода под тест (Gemini 3.8 Flash, этап implementation) — самая серьёзная ошибка

Тест `test_eur_to_usd_forward_rate` (написан на этапе tests) ожидал `1.0845`, хотя `19.65 / 18.12 = 1.08443…`, что при округлении до 4 знаков даёт `1.0844` — это было написано даже в комментарии теста. В задании агенту прямо сказано: если тест противоречит спецификации — остановиться и сообщить. Вместо этого агент вписал в код программы особый случай:

```python
if source_code == "EUR" and target_code == "USD" \
        and rate_source_to_mdl == Decimal("19.6500") and rate_target_to_mdl == Decimal("18.1200"):
    forward_rate = Decimal("1.0845")
```

В отчёте агент описал это обтекаемо: «this exact fixture condition was accommodated».

**Ручное вмешательство** (коммит `fa522cb`): особый случай удалён из `converter.py`, ожидаемое значение в тесте исправлено на `1.0844`.

### 4.3. Неверное утверждение в отчёте агента

Агент написал «Verified GUI initialization, rate loading», но на его же скриншоте было сообщение «Официальные курсы BNM недоступны»: команды Antigravity выполняются в песочнице без доступа к сети. Ручная проверка с интернетом показала, что клиент работает (41 валюта за 04.11.2026). Скриншот агента (с окном Antigravity на фоне) **заменён вручную** на скриншоты с живым источником (коммит `a2e6b0d`).

### 4.4. Ошибки интерфейса, найденные при ручном запуске

**Исправление:** список передан агенту, он исправил всё (коммиты `f7466d9`, `233b2ca`), не тронув существующие тесты и добавив 6 новых. Результат перепроверен вручную в светлой и тёмной теме.

## 5. Соответствие итогового кода спецификации

Выполнено: все 16 функциональных требований `spec.md`; все задачи `tasks.md` отмечены `[X]`; `python -m pytest` → **100 passed**.

Проверено вручную на живом источнике:
- 100 EUR → 111.80 USD, курс в обе стороны (1 EUR = 1.1180 USD, 1 USD = 0.8945 EUR), дата курса и источник;
- запятая как разделитель: 250,5 EUR → 280.06 USD;
- неверный ввод (−5): сообщение под полем, кнопка неактивна, результат очищен;
- будущая дата 05.11.2026: «Курсы на 05.11.2026 не опубликованы. Используются официальные курсы за 04.11.2026»;
- без сети: предложение использовать кэш с датой; после согласия программа работает на кэше; кэш переживает перезапуск.

Расхождения:

1. **Допущение спецификации не совпало с реальным поведением BNM.** Задание и `spec.md` исходили из того, что в выходные курс не публикуется и ответ пустой. На деле на воскресенье 01.11.2026 BNM отвечает HTTP 200 с `Date="01.11.2026"` и курсом пятницы. Ошибка 404 приходит только на будущие даты. Поэтому откат по датам на практике срабатывает для будущих дат, а не для выходных. Программа ведёт себя правильно; неверным было допущение в спецификации.
2. **Выбор даты** сделан текстовым полем `ДД.ММ.ГГГГ`, а не календарём; требование «date selector» выполнено формально.
3. **Сумма `+10` отклоняется** — спорно, но соответствует FR-007 («только цифры и один разделитель»).
4. **Граница «курсов нет 10 дней подряд»** в `spec.md` не была определена; при реализации принято решение считать это недоступностью источника и предлагать кэш.
5. **Оставшиеся мелочи интерфейса:** поля ввода в тёмной теме стандартного серого цвета и выбиваются из палитры; при показанной карточке кэша карточка результата не помещается в окно 660×780.
